ПРОДВИЖЕНИЕ — ЕДИНЫЙ КОМПЛЕКТ 6.5 (на основе приложения 6.4)

Это единый установочный пакет, чтобы не скачивать и не устанавливать по очереди 6.2, 6.3 и 6.4.
В нём нет обещания, что финансовая система полностью готова к реальным платежам.

ОДИН РАЗ:
1. Сделайте резервную копию текущей базы и сохраните старый ZIP.
2. В Supabase → SQL Editor → New query вставьте целиком УСТАНОВИТЬ_БАЗУ_ОДИН_РАЗ.sql и нажмите Run.
   Файл содержит три последовательные транзакции. При ошибке остановитесь и пришлите текст ошибки; не повторяйте вслепую.
3. По желанию выполните ПРОВЕРИТЬ_ТАБЛИЦЫ.sql. Ожидается 12 таблиц, если шесть старых уже были.
4. В config.js замените PASTE_YOUR_SB_PUBLISHABLE_KEY_HERE на свой publishable key (sb_publishable_...). НИКОГДА не вставляйте secret/service_role key.
5. Загрузите файлы приложения в корень GitHub Pages репозитория. SQL и инструкции в GitHub загружать НЕ НУЖНО.
6. На Android откройте сайт с интернетом, обновите страницу и проверьте тестовые записи.

ВАЖНО:
• Приложение внутри — проверенная по наличию файлов основа версии 6.4; не выдаём её за готовую финансовую версию 7.0.
• Не используйте пилотный финансовый учёт для реальных платежей до проверки миграции, RLS и расчётов.
• Старые карточки связываются вручную; платежи из старой таблицы payments не переносятся автоматически в studio_ledger.
• Автоматические списания, фоновые push, полноценная офлайн-синхронизация финансов и проверенная 2FA ещё не реализованы.
• При отсутствии резервной копии не выполняйте обновление SQL.
