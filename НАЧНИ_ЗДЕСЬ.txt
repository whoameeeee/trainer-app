ПРОДВИЖЕНИЕ 7.0 — КРУПНОЕ ОБНОВЛЕНИЕ (ТЕСТОВАЯ ВЕРСИЯ)

Сначала сохраните резервную копию Supabase и старый ZIP приложения.
Не используйте реальные платежи, пока не проверены доступы и расчёты на тестовых данных.

1. БАЗА ДАННЫХ
Если в проекте уже установлены база 6.5, ОБНОВЛЕНИЕ_6_7.sql и ИСПРАВЛЕНИЕ_СОЗДАНИЯ_СТУДИИ.sql, выполните в Supabase SQL Editor только ОБНОВЛЕНИЕ_7_0.sql.
Если предыдущие SQL не выполнялись, запустите их в указанном порядке (они находятся в архиве). Если любой запрос выдал ошибку, остановитесь; не переходите к следующему.
Выполнять SQL только в Supabase, не публиковать SQL-файлы на GitHub Pages.

2. ПРИЛОЖЕНИЕ
В config.js вставьте прежний sb_publishable_... (никогда не sb_secret_...).
В GitHub загрузите только веб-файлы из архива: index.html, studio.html, exercises.html, exercises-data.js, finance.html, client-links.html, config.js, sw.js, manifest.json, icon.svg, icon-192.png, icon-512.png.
Нажмите Commit changes. Дождитесь GitHub Pages. Перезапустите приложение на Android, при необходимости очистите только кеш браузера (НЕ данные приложения при несинхронизированных записях).

3. ПРОВЕРКА
Войдите под владельцем. Откройте «Студия и финансы» (новая страница studio.html).
Если студии нет — создайте её. В разделе «Клиенты» нажмите «Подключить старые карточки владельца».
Добавьте тестового клиента, назначьте индивидуальную цену и абонемент.
Проведите тестовое пополнение 1000 ₽ и оплату занятия 300 ₽ с депозита; остаток должен быть 700 ₽.
Создайте отдельный аккаунт сотрудника (через регистрацию на странице студии); владелец приглашает сотрудника по его email. Убедитесь, что сотрудник видит только своих клиентов и свои начисления.
Проверьте, что при недостаточном депозите операция отклоняется и повторная отправка одного запроса не списывает деньги второй раз.

4. ЧТО НОВОГО
Два типа аккаунтов: владелец и сотрудник. Клиенты — карточки без входа.
Приглашение сотрудников по email и доля 50% по умолчанию.
Старые карточки владельца подключаются к новой студии без удаления.
Индивидуальные цены, абонементы, депозиты, списания и отчёт с диаграммами.
Каталог упражнений MAT и отдельные виды оборудования, включая реформер.

5. ОГРАНИЧЕНИЯ
Это тестовая версия: не проведены сквозные тесты с вашим Supabase, не завершены push при закрытом приложении и полноценная офлайн-синхронизация финансов. Старые платежи автоматически не мигрируют. У старого расписания и нового кабинета студии есть отдельные экраны; новые карточки создаются с привязкой к старой таблице, но требуется проверка каждого рабочего сценария.
При неполадках остановите финансовые операции и пришлите точный текст ошибки без паролей и ключей.
