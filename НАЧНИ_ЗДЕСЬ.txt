ПРОДВИЖЕНИЕ 7.1 — ДЕНЕЖНЫЕ АБОНЕМЕНТЫ И НОВЫЙ ДИЗАЙН (ТЕСТОВАЯ ВЕРСИЯ)

1. Сохраните предыдущий ZIP и резервную копию Supabase. Не проводите реальные платежи, пока не проверите работу на тестовых данных.
2. Если версия 7.0 уже установлена, в Supabase → SQL Editor выполните ТОЛЬКО ОБНОВЛЕНИЕ_7_1.sql. Если нет, сначала установите предыдущие SQL по инструкции 7.0, затем ОБНОВЛЕНИЕ_7_1.sql. При любой ошибке остановитесь.
3. В config.js перенесите прежний sb_publishable_... ключ. НИКОГДА не используйте secret/service_role ключ в приложении.
4. В GitHub загрузите веб-файлы: index.html, studio.html, exercises.html, exercises-data.js, finance.html, client-links.html, config.js, sw.js, manifest.json и иконки. SQL-файлы в GitHub загружать не нужно. Нажмите Commit changes и дождитесь GitHub Pages.
5. Перезапустите приложение. В «Управление студией» сначала показываются клиенты и абонементы; финансы и аналитика — в конце. Для их открытия потребуется повторно ввести пароль аккаунта. При сворачивании приложения они блокируются. Это дополнительная защита интерфейса, не отдельное серверное шифрование: серверные права по ролям сохраняются.
6. ТЕСТ: создайте клиента, назначьте ему цену «Персональная» 2500 ₽ и «Сплит на реформерах» 3000 ₽. Оформите денежный абонемент на 15000 ₽. Списание персональной тренировки должно оставить 12500 ₽; реформера — 9500 ₽. Повторная операция с тем же ID не должна повторно списать средства. При нехватке остатка списание должно отклоняться.
7. Старые абонементы по количеству занятий остаются в истории, автоматически в денежные НЕ конвертируются. Старые депозиты остаются отдельным механизмом. Денежные абонементы учитываются как поступление при покупке и как выручка при проведении занятия; повторно суммировать обе суммы как выручку нельзя.

ВАЖНО: нет проверки в вашем реальном Supabase; версия тестовая. Отдельные экраны старого расписания и нового кабинета студии пока не объединены полностью. Push при закрытом приложении и полная офлайн-синхронизация финансов не реализованы.
