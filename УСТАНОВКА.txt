ПРОДВИЖЕНИЕ 6.0 — ПИЛОТНЫЙ МОДУЛЬ РОЛЕЙ И ФИНАНСОВ

1. Скачайте резервную копию из старого приложения и сохраните старый ZIP.
2. Откройте config.js и вставьте ТОЛЬКО sb_publishable_... ключ Supabase. Никогда не вставляйте secret/service_role.
3. В Supabase → SQL Editor выполните finance.sql один раз. Проверьте отсутствие ошибок.
4. В GitHub репозитории замените файлы содержимым этой папки и нажмите Commit changes.
5. Подождите GitHub Pages, обновите страницу. Откройте «Студия и финансы».
6. Войдите в существующий аккаунт. Владелец нажимает «Создать студию» только один раз.
7. Сотрудник должен предварительно зарегистрировать аккаунт. Владелец добавляет его по UUID пользователя Supabase.
8. Клиент регистрируется, вводит ID студии, отправляет заявку. Владелец принимает заявку.
9. На Android: Chrome → меню ⋮ → Установить приложение / Добавить на главный экран.

ВАЖНО:
- Это пилотный отдельный модуль, а не законченная бухгалтерия. Старые платежи/клиенты/тренировки из 5.0 НЕ мигрируются в новые таблицы автоматически. НЕ вводите повторно реальные платежи без сверки.
- «Финансы» защищены повторным вводом пароля и RLS. Полная двухфакторная авторизация, серверная проверка для каждого чувствительного действия, надёжные push-уведомления и полная офлайн-синхронизация финансов НЕ реализованы.
- Отказ заявки в пилоте не реализован (кнопка сообщает об ограничении). Для работы с реальными деньгами нужны аудит прав доступа, серверная модель депозитов и корректный расчёт прибыли.
- Никогда не публикуйте реальные клиентские данные, пока не протестированы права всех трёх ролей.
