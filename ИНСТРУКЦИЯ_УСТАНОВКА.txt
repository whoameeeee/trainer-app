ПРОДВИЖЕНИЕ 6.7 — ОДИН БОЛЬШОЙ ПАКЕТ

1. Сделайте резервную копию Supabase и предыдущей версии сайта.
2. Если после последнего скриншота у вас только 6 исходных таблиц, в Supabase SQL Editor сначала выполните УСТАНОВИТЬ_БАЗУ_ОДИН_РАЗ.sql. Если вы уже запускали его успешно — НЕ повторяйте.
3. Затем выполните ОБНОВЛЕНИЕ_6_7.sql (он включает 6.6; отдельно 6.6 запускать не надо).
4. При ошибке SQL остановитесь и пришлите текст ошибки; файлы сайта пока не меняйте.
5. Перенесите прежний sb_publishable_... в config.js. НИКОГДА не используйте sb_secret_... и не публикуйте пароль.
6. Загрузите HTML, JS, PNG, SVG, manifest.json, sw.js и config.js в корень GitHub Pages. SQL и текстовые инструкции в GitHub загружать не требуется.
7. В Chrome Android откройте сайт, обновите его и проверьте на ТЕСТОВЫХ аккаунтах.

ТЕСТЫ: владелец создаёт студию; клиент подаёт заявку; владелец одобряет; владелец пополняет депозит 1000; списывает 300 (остаток 700); списание 800 отклоняется; сотрудник не видит расходы студии; абонемент 2 занятия списывается дважды, третье списание отклоняется.

ДОБАВЛЕНО: серверные платежи с защитой от повторов, проверка депозита, процент сотрудника на дату занятия, атомарное списание абонементов, фильтр операций по датам, CSV, назначение тренера, остатки депозитов, автоблокировка финансов при сворачивании и через 3 минуты бездействия, обновлённый офлайн-кеш интерфейса.

ОГРАНИЧЕНИЯ: новая финансовая система требует интернета; автоматическая миграция старых платежей отсутствует; push при закрытом приложении отсутствует; отдельная серверная повторная аутентификация финансов и MFA не реализованы. Отчёты — управленческие, не бухгалтерские. До проверки RLS и платежей на тестовых аккаунтах не использовать с реальными деньгами.
